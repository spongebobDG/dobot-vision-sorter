# Architecture and safety invariants

## Runtime sequence

한 번의 선별 사이클은 다음 순서로 진행됩니다.

1. 스캔 위치에서 안정화된 프레임을 취득합니다.
2. YOLO 세그멘테이션 마스크에서 클래스, 중심, 각도를 계산합니다.
3. 독립 검증을 통과한 호모그래피와 물체 높이 보정을 적용합니다.
4. 로봇 작업 영역과 중앙 pick zone에 포함된 후보만 남깁니다.
5. 목적지 그리드에 빈 셀이 있는지 확인합니다.
6. 안전 높이에서 이동·회전한 뒤 저속으로 하강해 물체를 집습니다.
7. 정상/불량 그리드로 이동해 배치합니다.
8. 스캔 위치로 복귀하고 새 프레임에서 다음 물체를 다시 검출합니다.

이 구조는 물체를 여러 개 검출한 뒤 오래된 좌표를 순차적으로 사용하는 문제를 방지합니다.

## Safety invariants

로봇 명령은 다음 조건을 항상 만족해야 합니다.

- 원본 목표 좌표가 작업 영역 안에 있어야 하며, 범위 밖 좌표는 clamp하지 않습니다.
- XY 이동과 R축 회전은 설정된 안전 높이에서 수행합니다.
- 하강은 검증된 XY 위치에서만 수행합니다.
- 배치 그리드가 가득 차면 물체를 집기 전에 중단합니다.
- 그리퍼 명령이 실패하면 성공 상태로 진행하지 않습니다.
- 물체를 들고 있는 상태에서 오류가 나면 임의 위치에 놓지 않고 수동 복구를 요청합니다.
- 카메라 스트림이 끊기거나 보정 파일이 검증되지 않으면 실행을 중단합니다.

소프트웨어 검사는 물리적 비상정지를 대체하지 않습니다.

## Module boundaries

- `geometry.py`: 좌표, 작업 영역, 배치 그리드처럼 단위 테스트 가능한 순수 로직
- `calibration.py`: 보정 파일 검증과 픽셀→로봇 좌표 변환
- `dataset.py`: 데이터 누수 및 세그멘테이션 라벨 감사
- `vision.py`: Ultralytics/OpenCV 어댑터
- `robot.py`: Dobot 명령과 fail-fast 안전 이동
- `orchestrator.py`: 상태 및 대상 선택 규칙
- `run_sorter.py`: 카메라·모델·로봇의 실제 통합

## Placement feedback

배치 피드백은 기본적으로 꺼져 있습니다. 활성화하면 블록을 테이블 가까이 내린 상태에서 다음을 반복합니다.

1. 목표점 주변 제한 반경에서 동일 클래스 블록을 찾습니다.
2. 위치 및 각도 오차를 계산합니다.
3. 물체를 다시 안전 높이로 올립니다.
4. 설정 gain만큼 이동한 뒤 재측정합니다.

카메라가 그리퍼에 가려지거나 높이 보정이 맞지 않는 환경에서는 사용하지 않아야 합니다.
